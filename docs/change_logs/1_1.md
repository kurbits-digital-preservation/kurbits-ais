# V 1.1 (2026-09-03)
 
## Performance

- **Node tree** queries optimised. Fixed an N+1 pattern where every row triggered
  extra `COUNT` queries; child-existence is now computed in a single batched query.
- Added database indexes on `nodes(parent_id, local_ref)` and
  `nodes(institution_id, parent_id)` so expanding and listing children stays fast
  even under nodes with very many children.
- Child listing is now **paginated** (with a "Show more" control in the tree),
  so a node with tens of thousands of children no longer loads all at once.
- Subtree ref-code refresh rewritten from recursive (one query per node) to an
  iterative, one-write-per-descendant pass.
- OCR-extracted text is stored in a deferred column so large text is not loaded
  unless explicitly requested.

---

## Persistent identifiers

Resources can now carry multiple external / persistent identifiers.

- New **Identifiers tab** on each resource — add ARK, Handle, DOI, ISBN, or any
  admin-defined scheme; mark one primary per scheme; resolver links render when a
  URL template is configured.
- **Identifier schemes** are managed in Administration, including an optional
  external **generator service** (with custom auth headers, request-body template,
  and response path) so a new ARK/PID can be minted directly from a record via a
  **Generate** button.

---

## Locations & checkout

- **Click-through** from a resource (or a location item) to open that location.
- **Checkout categories** — checking an item out now records a *reason*
  (Reading room, Conservation, Exhibition, On loan, In transit, Digitisation, or
  any custom category). Categories are managed on the virtual *Checked out* location.
- **Return to previous location** — one click checks a checked-out item back in to
  exactly where it came from.
- **Move contents** — relocate every item in a location to another in one operation.
- **Quick move (barcode)** — scan a target location code once, then scan item
  reference codes to move them one after another; checked-out items are checked
  back in automatically.

## Process descriptions (BPMN)

Replaced the old Mermaid diagram tab with full BPMN 2.0 process modelling, for
process-based archival description (*verksamhetsbaserad arkivredovisning*).

The editor is powered by [bpmn-io](https://github.com/bpmn-io) 🔥

- **Process tab** on classification nodes with a curated BPMN editor (events,
  tasks, gateways, lanes, data objects, data stores).
- Records produced by a process are drawn as **data objects**; each can be named,
  linked to a records classification, and given records-management metadata:
  retention period, disposal action, security classification, medium/format,
  legal basis, and description.
- **Produced-by / used-by** activity links are read from the diagram's data
  associations and included in the export.
- **Records list** under each diagram, with **CSV export** of the full
  records-management detail.
- **"Produced by processes"** reverse lookup on a records class.
- Diagrams import and export as standard **BPMN 2.0 XML**.
- The dropdown values (disposal, security, medium) are admin-managed under a new
  **Records values** tab.
- The old Mermaid diagram feature was fully removed.

## Labels — WYSIWYG designer

Replaced the fixed label layout with a drag-and-drop designer.

- **Label designer** (in Administration): place fields, free text, barcodes,
  QR codes, and uploaded images on a label; drag to position, resize, rotate in
  90° steps, and set font, colour, and alignment.
- Designs are saved as **reusable templates** (per institution), one can be the
  default, and are chosen from the **Print labels** dialog.
- Optional **millimetre grid** and **preview with a real record** while designing.
- What you design matches what prints — layout is stored as fractions so the
  browser preview and the PDF agree.
- New **portrait** formats (archive box, spine) added alongside the existing
  landscape ones. Also fixed a pre-existing bug where the "Standard arkivetikett"
  format silently fell back to an Avery layout.
- Label fields include the resource's **parent** reference code, title, and dates.

## Search — facets

- Added **facets** to the search page — Classification, Agent type, Hierarchy,
  Level, and Status — each with counts, respecting the current query and filters.
- Clicking a facet narrows the results (single-select per facet).
- The **record-type toggle** (All / Resources / Agents) moved into the facet area.
- The filter panel was trimmed to just the **date range**, removing the overlap
  with facets.


---

## Export — EAC-CPF for agents

- Agents can be exported as standard **EAC-CPF 2010 XML** from the agent detail.
- Includes the agent's identity, dates, biography, notes (mapped to the
  appropriate EAC-CPF elements), external identifiers, **resource relations**
  (linked resources as `resourceRelation`), and **agent-to-agent relations**
  (`cpfRelation`).
- Verified to round-trip through the system's own EAC-CPF importer.

## Multi-language interface

- The interface can be switched between **English (default)** and **Swedish**.
- Language switcher in the top navigation; the choice is remembered.
- Infrastructure (react-i18next) plus login and navigation translated as the
  established pattern; remaining pages can be translated incrementally.

---

## Resource deletion

- A node with children can now be **deleted with a cascade**, after a confirmation
  that shows exactly how many descendant records will be removed. Leaf nodes delete
  with a simple confirmation as before.
